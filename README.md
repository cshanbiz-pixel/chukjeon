# 축제ON — 승인된 모바일 시안의 Astro 이식본

## 먼저 직접 할 일

이번 작업은 ZIP 파일로 전달하며 GitHub 저장소와 Cloudflare 배포 설정을 직접 변경하지 않았습니다. 기존 디자인 시안 사이트도 수정하지 않았습니다. TourAPI 연결이나 인증키 입력은 필요하지 않습니다.

1. ZIP을 내려받아 압축을 풉니다.
2. 기존 프로젝트 폴더를 백업합니다.
3. GitHub Desktop에서 `chukjeon` 선택 → `Repository → Show in Explorer`(Mac: `Show in Finder`)를 누릅니다.
4. ZIP 내부 `chukjeon` 폴더의 **내용물**을 저장소 루트에 복사합니다. `package.json` 바로 옆에 `src`, `public`, `data`가 있어야 합니다.
5. Node.js 22.x 최신 패치 버전(최소 `22.23.4`)을 설치합니다. 적합한 Node 24에서도 실행할 수 있습니다.
6. VS Code에서 저장소 폴더를 열고 `Terminal → New Terminal`을 누릅니다.

## 실행 명령

저장소 루트에서 한 줄씩 실행합니다.

```sh
npm ci
npm run check
npm run build
npm run dev
```

브라우저에서 `http://localhost:4321`을 엽니다. 터미널 종료는 `Ctrl+C`입니다. 빌드 결과를 직접 확인하려면 `npm run preview`를 실행하고 터미널의 주소를 여세요. `dist/index.html`을 더블클릭해서 열지 마세요.

## 이번 변경

- 승인된 시안의 390px 폭, 밝은 배경, 오렌지 포인트, 폰트·간격·카드·고정 액션바를 이식했습니다.
- 시안 CSS를 그대로 사용하고 Astro의 빈 목록·이미지 없음·비활성 더보기 등에 필요한 보조 스타일만 끝에 추가했습니다.
- 로고 원본 `public/images/logo.png`와 시안 사진 4개를 프로젝트 안에 포함했습니다. 실행 중 외부 이미지 서버나 API를 요청하지 않습니다.
- 기존 `data/festivals.json`은 **파일 내용까지 동일**합니다. 필드 이름, 값, 축제 10개, ID를 바꾸지 않았습니다.
- 기존 `src/types/festival.ts`, 날짜·데이터 함수, 패키지·잠금 파일, Astro 설정은 그대로 유지했습니다.
- `/`, `/[year]/[month]/`, `/f/[id]/`, `/404.html` 경로와 기존 월별 정적 생성 범위를 유지했습니다.
- JSON을 유지하기 위해 시안 사진·짧은 소개는 `src/lib/site-config.ts`의 샘플 화면 전용 매핑으로 표시합니다. 축제 제목·기간·정렬·관련 축제는 기존 데이터 기준이므로 시안의 가상 내용과 일부 다릅니다.
- 목록과 상세를 Astro가 HTML로 생성합니다. JavaScript를 꺼도 전체 카드·상세·이동 링크가 보입니다.
- 기존 1단계의 한국 현재 날짜 상태 배지/진행중·주말 집계만 클라이언트에서 유지합니다.
- 검색, 요약 바 클릭, 상태/해시태그 칩, 상세 태그, 소개 더보기, 길찾기, 공유, 일정 저장은 **모양만 표시**합니다. `aria-disabled="true"`와 `3단계에서 구현` 주석을 남겼습니다. 토스트·필터·다운로드·지도 앱 실행은 연결하지 않았습니다.
- 정렬 문구는 실제 기존 시작일순 목록에 대응하며 정렬 선택 기능은 없습니다.
- 시안의 계절 문구는 그대로 유지했습니다. 다른 계절 문구로 자동 변경하지 않습니다.

## 샘플 표시·검색 차단을 끄는 단일 설정

수정할 곳은 `src/lib/site-config.ts` 한 곳입니다.

```ts
export const siteConfig = { sampleMode: true };
```

현재 `true`이면 다음을 함께 적용합니다.

- 홈, 월별, 상세, 404를 포함한 **모든 HTML 페이지**에 `noindex, nofollow` 메타 태그.
- 정적 `/robots.txt` 내용: `User-agent: *` / `Disallow: /`.
- 화면 하단의 `샘플 데이터` 문구와 기타 샘플 안내.
- 승인된 시안의 참고 사진·소개 매핑.

실데이터 연결을 마친 뒤 `sampleMode: false`로 변경하고 `npm run build`로 다시 빌드·배포하세요. 그러면 noindex 메타를 제거하고 robots는 `Allow: /`로 바뀌며 샘플 안내와 샘플 사진 매핑도 해제됩니다. 설정만 끈다고 현재 가상 JSON이 실제 정보로 바뀌는 것은 아닙니다.

`robots.txt`는 이 설정에서 정적 생성하므로 `public/robots.txt`를 따로 추가하지 마세요. 캐시된 이전 배포 파일이 아닌 새 배포 결과의 `/robots.txt`와 HTML 소스를 확인하세요.

다른 시기에 빌드해 홈이 비어 있으면 `/2026/11/`에서 샘플을 확인하세요. 월별 페이지는 기존처럼 빌드 월 앞뒤 12개월 및 데이터에 있는 월을 생성합니다.

GitHub Desktop에서 Push origin을 누르면 연결된 Cloudflare Pages의 자동 배포가 시작될 수 있습니다. 이번 작업에서는 업로드·배포를 실행하지 않았습니다. 기존 Cloudflare 설정 `Astro / npm run build / dist / Node 22`는 유지하면 됩니다. Node 22의 실제 선택 버전은 최소 `22.23.4` 이상이어야 합니다.

검증 환경과 결과는 ZIP의 `VERIFICATION.md`에 있습니다.
